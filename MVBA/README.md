## Architecture constraints (VBA 7.1)

- **Runtime**: single-threaded, event-driven, COM-based. No async/await, no threads, no parallelism — never design around them. "Deferred" work runs on MicroStation **idle events**, not background threads.
- **Platform**: MicroStation CONNECT Edition / OpenCities Map PowerView / Atlas; .NET Framework 4.7.2+.
- **Host**: the MVBA host may be VBA7 (64-bit, `PtrSafe` / `LongLong`) or legacy VBA6 — bitness-sensitive code branches on `#If VBA7`. Win32 handles must be `LongPtr` under VBA7.

## Boot & lifecycle

Entry point: **`BootLoader.OnProjectLoad`**

1. `InitializeErrorHandler()` first (everything else logs through it).
2. `CustomPropertyHandler.IsLibraryDeclared()` — MicroStation loads Item Types only from the DGNLibs on `MS_DGNLIBLIST`, so a station where that variable ignores ARES has no custom properties at all. **Checks, never writes**: declaring it belongs to the installer, which appends one `MS_DGNLIBLIST > C:/ARES/Rsc/*.dgnlib` line to every `Personal.ucf`. The in-app **updater is not the installer** — it replaces files and never writes configuration, so a station kept current through updates alone never gains a new config line. A missing declaration is logged with its repair; boot continues.
3. `InitializeDGNHandlers()` → `New DGNOpenClose` (wires `Application` open/close events).
4. `InitializeInitialIdleHandler()` → an `IdleEventHandler`, flagged `MarkAsInitial`, that sets the caption, initializes translations + config, checks for updates, then removes itself. The flag is **per-instance on purpose**: dispatching on `LangManager.IsInit` ("translations loaded") instead silently skipped the entire boot sequence, because step 2's DGN-open status message loads translations before the first idle ever fires.

**Global objects** (declared in `BootLoader.bas`): `ChangeHandler` (ElementChangeHandler), `ErrorHandler` (ErrorHandlerClass), `ElementInProcesse` (ElementInProcesseClass), `ARESConfig` (ARESConfigClass), `CallStack` (CallStackClass, auto-instantiating).

**Teardown** `OnProjectUnload`: reset flags, then `Set … = Nothing` in dependency order (ErrorHandler last).

## Core element-processing flow (Event → Idle → Process)

Two phases. Capture is **synchronous** in the MicroStation event thread; processing is **deferred to idle** so it never blocks modeling.

**Phase 1 — Capture** (`ElementChangeHandler.IChangeTrackEvents_ElementChanged`)

```
If DetectAndSuspendBulkOperation() Then Exit Sub
If Not ARESConfig.IsInitialized Then Exit Sub
If Not IsAnyFeatureEnabled() Then Exit Sub
Select Case Action
  Add / Modify : ShouldQueueElement() -> QueueOrProcessDirect
  Delete       : ShouldQueueForDeletion() -> for each linked el: QueueOrProcessDirect
```
`QueueOrProcessDirect`: default → `ElementInProcesse.Add` → `EnsureIdleHandlerRegistered` (unchanged). If `ARES_Direct_Processing` → `ProcessDirect` (see below).

**`ARES_Direct_Processing` (default `True`)**: `QueueOrProcessDirect` routes an already-filtered element to `ProcessDirect` (calls `ProcessElement` synchronously, inline, from inside `IChangeTrackEvents_ElementChanged`) instead of `ElementInProcesse.Add` + idle. `DetectAndSuspendBulkOperation` still runs first either way, and is ALSO suppressed by `mbProcessingDirect` (mirroring the existing `IsIdleProcessingActive()` suppression for the idle path) — without this, a group's own Calculation/Actuator/Rendering cascade across several siblings in one `ProcessDirect` call could cross `ARES_Bulk_Threshold` and trigger a false bulk-suspend caused by ARES itself. Reentrancy is guarded by `mbProcessingDirect` — a reentrant call (e.g. `ProcessElement`'s own `.Rewrite` making MicroStation redispatch `ElementChanged` before the outer call returns) is NOT processed synchronously; it falls back to the deferred queue instead of being dropped, since that reentry lands back on the event entry point itself, invisible to `ProcessElement`'s `MAX_DEPTH`. The first fallback per session is logged (`mbReentrancyLogged`, log-only, no status bar). Setting the var to `False` falls back to the older deferred (queued) path, kept available for rollback or future diagnosis of a reentrancy issue.

**Phase 2 — Deferred** (`IdleEventHandler.IEnterIdleEvent_EnterIdle`)

```
mbIsProcessing re-entrance guard
First idle ever -> HandleInitialIdle (caption, translations, config, UpdateChecker) then self-remove
Ensure ARESConfig.Initialize
If ElementInProcesse.HasElements -> ProcessPendingElements   else CleanupHandler
```

**`ChangeHandler.ProcessElement(oElement, Depth=0)`** — `MAX_DEPTH = 20` recursion cap. At Depth 0 (before the graphic-group=0 skip): if `ARES_Auto_Properties` → `PropertyTagging.ApplyPropertyRules` (self-attach + `@` group push + `@` pull); then if enabled → `PropertyCalculation.ProcessElement` (bearing pass + trigger-cell pass); then if enabled → `PropertyActuator.ProcessElement` (paints Color/Level from a pilot property); then if enabled → `PropertyRendering.ProcessElement`. The order is the doctrine: **tagging attaches → calculation fills → actuator paints → rendering writes the text**, so an element added to a labelled group is attached, valued, painted and displayed in ONE pass. Deletion needs no dedicated calculation hook: deleting a trigger cell already re-queues its former group members, whose bearing pass re-resolves each carried calc property against the current group (surviving cell's text, or `""`).

- **Text/cell elements**: nothing left to do beyond the Depth-0 hooks above — the legacy `ONLY_COLOR` colour-sync hook (Branch 1: sync color from linked geometry, FillMode = 2 special case) is **retired** (2026-08-24), superseded in production by `PropertyActuator`'s `GroupColor` pilot property, which repaints a cell's own sub-elements without the header-write corruption bug the legacy hook was never exposed to (see `PropertyActuator.ActuateColor`'s header comment).
- **Branch 2 — geometric**: gated on `PropertyCalculation.IsEnabled AND (HasGroupLengthRules OR HasGroupColorRules OR HasGroupPropRules)`. `Link.GetLink` → for each linked element: `ElementInProcesse.Add`, then recursive `ProcessElement(linkedEl, Depth + 1)` (direct-processing mode: a full `bRunEngines:=True` pass instead). Fires on any `ElementChanged` for a grouped, non-text/cell element, including a pure custom-property edit — confirmed to fire reliably (debugger-verified). **Cascade-trigger rule** (root-caused live 2026-09-01, see `mvba-cheatsheet.md`): a model scan run INSIDE an element's own `ElementChanged` callback still returns its PRE-change state (the model commits after the callback returns); and an Item edit raises TWO native callbacks — Modify (3), where even `AfterChange` still holds the old Item value, then the undocumented action 17 (`CHANGE_TRACK_ACTION_ITEM_COMMITTED`), the first where `AfterChange` carries the new one — so `ElementChangeHandler` routes 17 like a Modify (one extra synchronous pass per user Item edit; ARES's own writes' 3+17 echoes are deferred and deduped, idle work unchanged). Branch 2's synchronous sibling pass runs inside that callback, so a pull source (`GroupProp`/`GroupColor`/`GroupLength`) re-scanning the trigger from a sibling read it one edit behind; push sources (`Cell*`/`Lvl*`, which read the trigger off its own handle) never did. Fix: `ProcessElement` publishes the Depth-0 trigger (`PropertyCalculation.SetCascadeTrigger`, cleared on every Depth-0 exit) and `PropertyCalculation_SourceEval.FreshHandle` redirects a pull source's read to it when a scanned candidate has the same ID. The reentrant echo a member's render write raises is still deferred to idle on purpose — it runs post-commit and is the safety net (a same-day attempt to drop such echoes was reverted: it caused a deterministic one-edit lag). `RecalculateSelection` remains the manual escape valve for any gap in automatic propagation.

**Idle-handler lifecycle invariants** (hard-won — do not regress):

- ONE persistent `IdleEventHandler` instance, created lazily, only added/removed from the idle list — never `New`-ed per batch (recreating caused ObjPtr reuse + stale-handler desync, so the queue never drained).
- `CleanupHandler` guards queue-drain/flag-reset with `ChangeHandler.IsActiveIdleHandler(Me)` so an orphan (the boot one-shot, or a handler left after `ChangeHandler` was replaced) cannot disturb the live one.
- Real attachment state (`mbChangeTrackingAttached`) is decoupled from the bulk "suspended" flag. `ReinitChangeTrackingForNewFile` is the single source of truth on file open; `AttachChangeTracking` / `DetachChangeTracking` are idempotent.

**Bulk-operation detection** (`DetectAndSuspendBulkOperation`): frequency-based — `ARES_Bulk_Threshold` calls within `ARES_Bulk_Interval` ms → `SuspendAndScheduleResume` (detach tracking, clear queue, register `ReRegisterIdleHandler`, which re-attaches on the next idle). Self-heals an orphaned suspend flag. Suppressed during ARES's own idle writes (`IsIdleProcessingActive`).

## Features

Key-in names and configuration variables are in the [wiki](https://github.com/Asketyll/ARES/wiki); below is the implementation summary.

- **Auto Lengths — REMOVED.** Superseded by Property Calculation (`GroupLength` source) + Property Rendering (`Prop[...]` token), which reproduce its output byte-for-byte. Its two key-ins (`ForceUpdateLength`, `EditAutoLengthsOptions`) and three config variables (`ARES_Auto_Lengths`, `ARES_Update_Lengths`, `ARES_Update_Color_With_Length`) are gone. `ARES_Length_Triggers` / `ARES_Length_Trigger_ID` are **deliberately kept with no reader** as a documentary trace for the manual conversion of old drawings (see `ARESConfigClass`); `ARES_Length_Round` survives as the default decimals of the `Length`/`GroupLength` calc sources. Two behaviours were NOT carried over: the colour written *with* the length, and the interactive multi-geometry disambiguation — the latter replaced by a status warning (`CalculationMultipleGeometries`).
- **Zoning** (`Zoning.bas`; `RunZoning` = merged / round caps, `RunOutline` = tight per-element, unmerged / flat caps): offset buffer per element type (Line → stadium, Arc → annular/pie sector, Ellipse → donut, Cell → rotated rounded rect), optional `GetRegionUnion` fuse. Round-vs-flat caps via `CapRoundAt` (flat only at true free ends). Both share the engine but have separate option sets + GUIs: `RunZoning`/`EditZoningOptions` read `ARES_Zoning_*`, `RunOutline`/`EditOutlineOptions` read `ARES_Outline_*` (own source level, distance, output symbology).
- **Zone Export** (`ExportLengthInRegion.bas`; `ExportLength`): for each element, `Length.GetPartialLengthInsideZones` (length inside zone polygons), aggregated by Style/Level/Color/ID (`ID` = one row per element via `DLongToString`; GUI display "vide"/"(none)"), written to a new `.xlsx`. An optional `ARES_Zone_Export_Level` filter (`|`-list; empty = all levels) restricts which measured elements are counted (non-existent names are ignored, reported on the status bar). An optional **per-zone breakdown** (checkbox `ARES_Zone_Export_Per_Zone`) additionally splits each group by zone (long format `Zone | group | length`, one row per zone×group, keyed by scan index so same-named zones stay separate rows; the zone-label cell is then visually merged over its rows, with a thin border grid + between-zone separators — presentation only), each zone labelled by a custom property read from the zone element (`ARES_Zone_Export_Zone_Property`; empty/absent → `Zone <n>`). A GUI checkbox "Open once exported" surfaces `ARES_Zone_Export_Excel_Visible`. The Excel COM lifecycle is carefully managed (never quits the user's own session).
- **Cable Report** (`CableReport.bas` + `CableReport_GUI_Options`; `ExportCableReport` / `EditCableReportOptions`; own `ARES_CableReport_*` option set — a separate feature from Zone Export, not a mode of it): one Excel row per cable. Cables = every `GetPartialLengthInsideZones`-capable type on `ARES_CableReport_Cable_Level` (`|`-list; missing names ignored + status, all missing aborts). **Repere** = the configured property read off the nearest `CellHeader` within `ARES_CableReport_Search_Radius` of each endpoint via `GetElements.FindNearestElement` (geometric proximity, NOT graphic group; `RequirePropertyName` filter so an unrelated cell in the radius never wins), written `start - end`; closed Shape/ComplexShape get none. **Nature/Longueur** = read verbatim off whichever `Link.GetLink` member carries each. **Soil-type pivot** = per zone (Shape/ComplexShape on `ARES_CableReport_Zone_Level`, fallback `ARES_Outline_Output_Level`) with partial length > 0, summed under `cableKey & vbTab & label` — cable-major, so same-labelled zones for one cable ADD up (the opposite of Zone Export's zone-index-major key); columns sorted case-insensitively, empty cell never 0. Property names validated against the ARES DGNLib (invalid → status, column blank). A missing Repere/Nature/Longueur is an expected drawing gap: blank + row counted incomplete in the final status, never logged. Excel COM lifecycle = `ExportLengthInRegion.WriteToExcel`'s contract. **Shared trenches**: a zone holding ≥ 2 cables is a shared trench and gets its OWN pivot column, keyed `<label> (n)` (`CH2C (2)`) next to the plain `<label>` — several coexist, and one cable can appear in several (start shared with one cable, end with another). The key identifies the sharing GROUP, not just the count: two `TA1` zones shared by different pairs (A+B, A+C) give two columns (`TA1 (2)`, `TA1 (2) #2`), while zones with the same members merge. Since the key depends on the zone's cable count, the per-cable loop only records raw per-(zone, cable) lengths (`RecordZoneLengths`) and `BuildPivotAndSharedTrenches` derives columns/pivot/cross-marks/footers in one post-pass. Rows keep each cable's own length; a 4th fixed column "Shared with" names the other cables (Repere, else `#<row>`); two-row footer per column: `Cable totals` (plain Σ) vs `Trench to dig (deduplicated)` = Σ over zones of the MAX in-zone length (needs one common zone; overlapping zones not detected). **Excel typing**: `TryAsNumber` writes a purely numeric Longueur as a real Double — a String assigned to `Range.Value` is parsed with the INVARIANT locale, so `"493,6"` was stored as text while ARES-computed cells were numeric. A cable counts as OCCUPYING a zone only past `ARES_CableReport_Cross_Factor` x `ARES_Outline_Distance` (default 3.5, config-only - no GUI control): below that it is merely crossing, and two crossing trenches each hold the other's cable for about their own width, which used to be reported as a half-metre shared trench. A factor of 2 IS one trench width, a perpendicular crossing's own value - hence the strictly-greater test; oblique crossings measure width/sin(angle) and need the extra margin. Diagnostics: `DiagCableLengths` / `DiagZoneOverlap`.
- **Region Split** (`RegionSplit.bas` engine + `RegionSplitLocate.cls` single-click driver; `SplitRegion`): cut a Shape/ComplexShape in two from one datapoint, perpendicular (or radial on arcs) across the interior. **Gapless cut (2026-08-31):** two independent `GetRegionDifference` calls, each against the SAME knife width/over-extension but offset entirely to one side of the cut chord (near edge exactly on the chord, far edge at `2 * half-width`); the exact-edge piece from each call (its boundary passes through both the entry and exit points) is kept, so both halves share the same cut line with no gap — a `MergeRegion` right after a `SplitRegion` can recombine them. Each call must yield exactly one exact-edge piece (2 total), else the split fails cleanly with no model change. **Anti-destructive invariant**: build, add and validate BOTH halves before deleting the original (`ARES_RegionSplit_Keep_Original` keeps it).
- **Region Merge** (`RegionMerge.bas` engine + `RegionMergeLocate.cls` two-click driver; `MergeRegion`): fuse two Shape/ComplexShape regions, picked by two successive datapoints, into one via `GetRegionUnion`. The merged result inherits the FIRST clicked region's level + symbology; no custom ARES property is carried over. **Anti-destructive invariant**: build, add and validate the merged result before deleting both originals (`ARES_RegionMerge_Keep_Originals` keeps them). Disjoint/non-overlapping regions are REJECTED (no model change) rather than silently recoloured (decided 2026-08-27, after live testing).
- **Property Tagging** (`PropertyTagging.bas`; automatic; options via `EditPropertyTaggingOptions` → `PropertyTagging_GUI_Options`; master switch `ARES_Auto_Properties`): **the sole attach/detach engine for custom properties**. On element add/modify, attaches per `ARES_Property_Rules` — **grammar v2 (clean break; the old `level[:type]=…` format is an invalid rule, ignored fail-closed)**: a rule is `[@]cond[&cond]*=prop|prop`, conditions `Lvl[name|name]` / `Cell[name|name]` / `Type[type|type]` (`Type[Cell]` = special "any cell" token). Inside `[...]` everything is literal except `|` (`;`/`[`/`]` forbidden in names — levels like `Poste=HTA` or `R&D` are declarable); `&` = AND; `!` prefixing a condition = **strict** logical negation (a line satisfies `!Cell[A]`; "a cell but not A" = `Type[Cell]&!Cell[A]`); `*`/`?` wildcards via `Like` (`#` escaped, case-insensitive); a leading `@` = rule modifier — attach to the OTHER members of the matched element's graphic group (never itself; nothing without a group); no `@` = attach to the matched element itself. **`@` is membership-convergent**: push at match time + **pull** at each member's own Depth-0 processing (`PullGroupProperties` — a grouped element receives the props of every `@` rule matched by another member), so an element added to an already-tagged group is tagged at its next pass without the matcher being re-touched; ONE shared `Link.GetLink` per processed grouped element feeds both directions, short-circuited by the `mbHasGroupRules` cache when no `@` rule exists; attach-only — membership loss never detaches. Unknown keyword/type = rule rejected (future keywords non-breaking); `(`/`)` reserved. **One bracket-depth-aware parser** (`ParseOneRule`) is shared by the runtime (fail-closed skip), `ValidateAndNormalizeRule` (targeted reason OR the **compact canonical form** — what the editor stores) and `RuleHasNoEffect` (dead-rule detector: same-keyword disjoint positive lists, `Cell` vs non-cell `Type` in both senses; no verdict with wildcards; returns the conflicting segments). Attaches are `HasItems`-guarded idempotent; the level is read once and passed so `Cell`/`Type` rules reach a level-less cell header; `DetachRuleProperty(El, P)` remains the only sanctioned detach service. The options GUI edits the rules **one at a time** through the editable dropdown (pick → edit → commit = replace; free-type = add; empty = delete; trailing "new rule" sentinel), every commit validated + normalized (malformed → status-only `PropertyRuleInvalid`), with a **colored syntax preview** under the combo (runtime labels: `@` pink, `&` dark blue, `!` orange, wildcards green, dead-rule segments red). Ungrouped rule-matching elements are also queued (beware very broad negation-only rules — bulk detection is the backstop); everything applies at `Depth = 0` only.
- **Property Calculation** (`PropertyCalculation.bas`, ex-Property Propagation; options via `EditPropertyCalculationOptions` → `PropertyCalculation_GUI_Options`; master switch `ARES_Property_Calc`, ON by default since the Auto Lengths removal): **a value-calculation engine only** — it never attaches/detaches (any direct attach/detach in this module is a review BLOCKER); it writes only where a property is **already attached** (the frontier `IsItemAttachedToElement`). **AWAKE (phase 2):** each custom property's value comes from a **calc rule** in `ARES_Calc_Rules`, grammar `Prop[name] [&condition]* = Source`, built on the shared `RuleGrammar` conditions (`Lvl/Cell/Type`, `&`, `!`, `*`/`?`). `Prop[name]` is the **target** (one name, **no wildcard**, syntactic-only — the frontier is the runtime guard). **Twenty-one sources** (keyword + optional `[arg]`, arity-checked, unknown rejected fail-closed), in two families. A **GROUP source** scans the graphic group **including the bearing element itself** and reads off the MATCHING member, not off the bearer: `CellText[pattern]` (that cell's full text via `StringsInEl.GetConcatenatedText` — an ungrouped matching cell is a group of one), `CellCoord`/`CellId`/`CellLvl`/`CellColor`/`CellStyle`/`CellWeight[pattern]` (that same cell's coordinates / `DLongToString` id / level name / color index / line-style name / line-weight — this is how a member reads the TAGGING cell's own attributes rather than its own; `CellId` is stable and never pushed, every other `Cell*` IS), `LvlColor`/`LvlStyle`/`LvlWeight[pattern]` (epic 16 follow-up: same self-included scan, but matched by a member's LEVEL NAME instead of a cell's name, no element-type restriction — covers a group authority that is a plain geometry on a named level; `LvlColor`/`LvlWeight` resolve MicroStation's `ByLevelColor`/`ByLevelLineWeight` sentinel via that member's own Level, `LvlStyle` reads its `LineStyle.Name` directly; pushed by their own trigger-level pass, its own `CalculationMultipleLvlTriggers` status so the wording never claims "cells" for a collision that may have none), `GroupColor` (2026-08-24, retired `ONLY_COLOR` hook parity prerequisite: the color of the FIRST linked element, `Link.GetLink` WITHOUT self-inclusion — the ONLY self-excluded GROUP source in the module, since color has no type filter to protect a self-match the way `GroupLength` does; no name/level pattern either, mirrors the retired hook's own candidate pick exactly. Resolved through `ResolveFillAwareColor`, shared with `CellColor`/`LvlColor` — RETROACTIVE change on those two, 2026-08-24: a `FillMode=2` `ClosedElement` candidate now yields its fill color instead of its outline `.Color`, 0/255 falls back to outline, recopied verbatim from the legacy hook. ≥ 2 linked elements raise the one-shot `CalculationMultipleColorCandidates` — new disclosure, not a legacy behaviour. No trigger/push pass of its own: `HasGroupColorRules` gates Branch 2 exactly like `HasGroupLengthRules`), `GroupProp[PropertyName]` (reads another custom property's VALUE off the first linked, self-excluded candidate that has a genuinely non-empty value — unlike `GroupColor`, FILTERED by `IsItemAttachedToElement` AND non-emptiness, since an arbitrary property has a real unattached/still-empty state a color doesn't, and an attached-but-empty candidate is itself an unresolved receiver, never a valid donor. Lets a value be tagged once on a group's authority element and reported to every linked sibling instead of tagged individually — e.g. a cable's `Nature`, read by each of its linked texts. `""` when none found or every carrier is empty; ≥ 2 REAL-valued candidates raise `CalculationMultiplePropCandidates`. No trigger/push pass of its own either: `HasGroupPropRules` gates Branch 2 the same way. **Donor/receiver symmetry**: the rule must exclude the donor via a condition, or the donor's own bearing pass resolves against its still-empty receivers and can blank/detach its real value on first calculation — see `calc-rules-grammar.md`), and `GroupLength`/`GroupLength[n]` (the length of the FIRST length-capable element in the group, found by TYPE not by name pattern — the common case being a property on a TEXT/CELL fed by the linked line — this is what replaced Auto Lengths; ≥ 2 candidates raise the one-shot `CalculationMultipleGeometries` status; default decimals = `ARES_Length_Round`). A **SELF source** reads the bearing element's own attribute: `Value[text]` (fixed literal), `Coord`/`Coord[n]` (its OWN `"X;Y"` via a verified anchor cascade `Origin → CenterPoint → Centroid → Range-centre`, master units, `Round`+`CStr`, default decimals = `ARES_Round`), `Id` (its OWN `DLongToString`), `Lvl`/`Color`/`Style`/`Weight` (its OWN level name / color index / line-style name / line-weight, guarded by `IsGraphical`, never fabricated), `Length`/`Length[n]` (its OWN geometry length via `Length.GetLength`, ONLY when it is itself Line/Arc/Shape/ComplexShape/ComplexString — `""` otherwise). Every `Cell*` source's `pattern` may be several `ARES_VAR_DELIMITER` (`\|`) - separated alternatives (`MatchesAnyPattern`, same grammar as a tag/calc CONDITION's `Cell[name|name]`). **Several rules for one property: the FIRST that matches wins** (order = priority; specific rules first). One bracket-depth-aware parser (`ParseCalcRule`) backs the runtime cache, `ValidateAndNormalizeCalcRule` (targeted reason OR the compact canonical the editor stores) and `CalcRuleHasNoEffect` (dead-condition detector via `RuleGrammar.ConditionsHaveContradiction`, the `Prop` target ignored). **Engine:** two Depth-0 passes — a **bearing pass** (fill/recompute each carried property from its first-matching rule; also the delete-reconcile — a re-queued member re-resolves to the surviving cell's text/coord, or `""`), a **trigger-cell pass** (a cell matching any PUSHABLE `Cell*` source — `IsPushableCellSourceKind`, i.e. everything except `CellId` — pushes its attribute to the OTHER members MicroStation did not re-queue, first-match guarded; `CellId` never needs a push, an ID cannot change), and a **trigger-level pass** (`IsTriggerLevel`/`PushLvlDerivedValuesToMembers`, epic 16 follow-up: same shape, keyed on Level name instead of cell name, no element-type restriction — a DELIBERATELY separate pass/status pair, not folded into the cell one, since the trigger predicate and the "cells"-worded status differ). `GroupLength`/`GroupColor`/`GroupProp` need no push of their own: their candidate is found by LINK not by name, so `ElementChangeHandler`'s Branch 2 reacts when that linked element changes — gated on `PropertyCalculation.(HasGroupLengthRules Or HasGroupColorRules Or HasGroupPropRules)`, and calling `ProcessElement` on each linked sibling **inline** rather than only through the queue (a queued Depth-0 pass never arrives — `IdleEventHandler.CleanupHandler` wipes Branch 2's queue-add first). Every write routes through `ApplyValueToSibling` (frontier + compare-before-write + non-empty→empty **transition guard** + `ARES_Calc_Detach_Empty` delegated detach — all loop-safety BLOCKERs) and **addresses the target property's OWN item** (`ItemName:=P` — resolving the first-attached item instead misdirected calc writes on elements carrying ≥ 2 properties). One-shot statuses `CalculationNoTarget` / `CalculationValueRejected` / `CalculationMultipleTriggers` / `CalculationMultipleLvlTriggers` / `CalculationMultipleColorCandidates` / `CalculationMultiplePropCandidates` / `CalculationMultipleGeometries` (all on SEPARATE flags on purpose: a group can hold competing cells, competing level-matching elements, competing `GroupColor`/`GroupProp` candidates, AND competing geometries at once). The options GUI (`EditPropertyCalculationOptions`) edits the calc rules one at a time through `ComboBox_CalcRules` + a coloured preview `Frame_CalcPreview`, reusing the shared `RuleEditorUX` (same mechanics/sentinel/close-flush as the tag rule editor) driven by `ValidateAndNormalizeCalcRule` / `CalcRuleHasNoEffect`; the preview bolds all twenty-one source keywords alongside `Prop`/`Lvl`/`Cell`/`Type`; a malformed rule is refused status-only (`CalcRuleInvalid`, never logged).

- **Property Actuator** (`PropertyActuator.bas`, epic 16; master switches `ARES_Actuate_Color`/`ARES_Actuate_Level`, both OFF by default): the fourth engine, and the first that REVERSES the read doctrine — property VALUE → graphic ATTRIBUTE (`Color`/`Level`), instead of attribute → property. Pure **SELF reaction, no group logic of its own**: its source is already stable-pushed by `PropertyCalculation` (`CellColor`/`CellLvl` or, since 2026-08-24, `LvlColor`/`LvlStyle`/`LvlWeight`), so by the time it runs the element's own pilot property is already fresh — it only reads its own pilot property, compares to its own attribute, writes if different. Runs Depth 0, after Calculation, before Rendering. Pilot properties are **fixed and reserved**, not user-configurable: `ARES_Color`/`ARES_Lvl`, attached via `PropertyTagging`'s existing `|` multi-property grammar (e.g. `Lvl[WALLS]=Commune|ARES_Color`), authored as `Prop[ARES_Color]=CellColor[TRIG*]` in `ARES_Calc_Rules` like any other property (the `Prop[...]` wrapper is mandatory - do not drop it, it is easy to confuse with `PropertyTagging`'s bracket-only condition grammar). Trigger exclusion is its own fail-closed wrapper per source family (`IsProtectedTriggerCell`/`IsProtectedTriggerLevel`), and a SELF-source ratchet refusal prevents a pilot property whose own calc source is the very attribute being actuated. Since 2026-08-24, `PropertyCalculation.ApplyValueToSibling` calls `PropertyActuator.ProcessElement` inline right after pushing a value to a group member — that member is never the element `ElementChangeHandler` itself queued, so without this call its attribute stayed stale until directly touched. On a cell, a repainted sub-element in `FillMode=2` has its own fill color saved and restored around the write (retired `ONLY_COLOR` hook parity). The cell HEADER's own `Color` is deliberately never written, unlike a non-cell element: doing so triggers a MicroStation-native `ByCellColor` cascade that silently corrupts sub-element `FillMode`/`FillColor` before the repaint loop even runs — see `PropertyActuator.ActuateColor`'s header comment for the full investigation (2026-08-24).
- **Property Rendering** (`PropertyRendering.bas`, epic 15 phase 1; master switch `ARES_Text_Render`, ON by default since the Auto Lengths removal; key-ins `BindPropertyRender` + `EditPropertyRenderingOptions` → `PropertyRendering_GUI_Options`, which also hosts the two DISPLAY settings inherited from the removed Auto Lengths form — `ARES_Update_ATLASCellLabel`, `ARES_Cell_Is_Label_Name` — since `CellRedreaw`, their only consumer, is called by the renderer's sole text write; no help button there on purpose: the panel has no rule grammar to document): **the sole text writer** — the third doctrine line after *Tagging is the only attacher* and *Calculation is the only value writer*. It never writes a user property value, and never attaches/detaches anything itself (the `ARES_Render` attach/detach is delegated to `PropertyTagging.AttachRenderMetadata` / `DetachRenderMetadata`, so the attach choke point stays unique). A **`Prop[Name]` token** typed in a text is **fully replaced** at render time — `Ligne Prop[Len] m` → `Ligne 13,3 m` — and the rendered text is CLEAN: no visible scaffolding ever survives. The token spelling is deliberately the one the calc grammar already uses; the name is matched case-insensitively against `GetCustomPropertyNames()`, and an unknown name stays literal (fail-closed). Whole-value mode is simply a Template that IS one token.
  **The binding is hidden metadata**, not the text and not the graphic group: a second, INTERNAL `ItemTypeLibrary` **`ARES_SYS`** (authored in the same `ARES_Custom_Properties.dgnlib`) holds one ItemType `ARES_Render` with two String properties — `SchemaVersion` and `Entries`, a serialised list of `{SubId, Template, LastValues}` records (delimiters `Chr(1..4)`; a value carrying one of them, or CR/LF, is refused at the choke point). Because `ARES_Render` is a **2-property** ItemType, every access must name `ItemName` AND `LibraryName` explicitly and pass the new `bNoFallback` flag — `CustomPropertyHandler`'s single-property fallback would otherwise hand back `Entries` when `SchemaVersion` reads empty, silently. `GetCustomPropertyNames()` stays bound to the user library, so `ARES_SYS` never leaks into any picker.
  **The last rendering is never stored — it is COMPUTED** as `Expand(Template, LastValues)`, and that is what makes a hidden template safe. Per entry, after an `IsLocked` test and a successful NON-EMPTY read: **(1)** visible = `Expand(Template, current values)` → strict no-op (the loop terminator: no text write, no `Rewrite`, no metadata write); **(2)** visible = `Expand(Template, LastValues)` → the values moved → re-render and store; **(3)** otherwise (positive proof of a user edit) → **per-token release**: the Template's literals locate each span, a span still equal to its last value is re-tokenised and keeps updating, anything else becomes static text and drops its token; an ambiguous alignment falls back conservatively (keep only the verbatim `Prop[Name]` substrings) + status, and the re-authored Template is re-validated exactly like a first author; **(4)** no metadata + valid tokens → first author, **hybrid policy**: auto-bind only when every token's property is ALREADY attached to the element (attachment is the intent signal), otherwise the token stays literal and `BindPropertyRender` is the entry point. An **empty value renders the token's own literal text** as the "unset" cue **and stores an empty `LastValues` entry** — without that write an unset→reset round trip lands in branch 3 and silently flattens the binding. Values are copied **VERBATIM** (no `CStr`, no `Format`, no locale transform — that is what stops two stations rewriting each other's decimal separator); a non-string typed value yields the literal token + status. **Writes are ordered text first, then metadata**; a metadata write that fails after the text landed restores the text and transitions nothing.
  **Coexistence with Auto Lengths is asymmetric — on a text carrying a token, THE RENDERER WINS**, and it is enforced in code in ONE direction only: the renderer does *not* check whether its own expansion looks like an active legacy trigger — it deliberately writes `(12.3m)` when the Template says `(Prop[Len]m)`, which is the flagship case and the whole point of superseding Auto Lengths. The single guard is Branch 1's `IsRenderBound` skip, and it suffices because rendering runs *before* Branch 1 in the same pass: the renderer binds first, and Branch 1 then stands down on that element. A text the renderer does not own is untouched and stays legacy territory — including one whose binding is later RELEASED, which hands it back to Auto Lengths, as it should. **Containment**: `GetExcludedSubIds` keeps a rendered sub-text out of the `CellText[...]` value that governs it — keyed on metadata PRESENCE, deliberately NOT on the feature flag, because a switch must never mutate data. A **bounded repaint hop** (`NoteDirtyGroup`, appended by `ApplyValueToSibling` on any value state change including the emptying one; drained over the noted element AND its `Link.GetLink` siblings, always through the FULL state machine, never a blind render, re-entrance-guarded and cleared every pass) refreshes a sibling the pipeline does not re-queue. All refusals are status-only and one-shot; only the schema and missing-library self-disables also write ONE English log line. **Known phase-1 limits**: a `GroupLength`-fed token does not refresh on a pure geometry stretch; there is no `RenderAll`/audit/unbind key-in yet; and a DWG/V7 round trip strips the items, so the clean text survives but the binding is lost.

## Configuration system

- `ARESConfig` (global) holds ~35 vars; each `ARES_MS_VAR_Class` write-throughs to MicroStation on `.Value` assignment. First run seeds defaults (`Config.GetVar` == `ARES_NAVD` → write default).
- **Key vs field name differ**: the MS key `ARES_Round` maps to the in-code handle `ARESConfig.ARES_ROUNDS`. Always check both.
- **Import/export** format: `KEY=VALUE:::DEFAULT=…:::MODIFIED=…`, header `# Version: <ARES_CONFIG_VERSION>` (currently `1.0.1`, distinct from the MVBA product release).
- List-typed values are split on `ARES_VAR_DELIMITER` = `|`.
- Shared compile-time constants live in `ARESConstants.bas`; module-private implementation constants (e.g. `MAX_DEPTH`, `EPSILON`, URLs) stay local to their module.

Developer-relevant / automatic vars (not all are surfaced by a key-in):

| Key | Default | Used by |
|-----|---------|---------|
| `ARES_Bulk_Threshold` / `ARES_Bulk_Interval` | 10 / 1000 ms | bulk-operation detection |
| `ARES_Round` | 2 | default rounding for length computations |
| `ARES_Auto_Properties` / `ARES_Property_Rules` | True / (empty) | PropertyTagging switch + v2 rules `[@]cond[&cond]*=prop\|prop ; …` (cond = `[!]Lvl\|Cell\|Type[name\|name]`) |
| `ARES_Property_Calc` / `ARES_Calc_Rules` | **True** / (empty) | PropertyCalculation switch + calc rules `Prop[name][&cond]*=Source ; …` (Source = `CellText\|CellCoord\|CellId\|CellLvl\|CellColor\|CellStyle\|CellWeight\|LvlColor\|LvlStyle\|LvlWeight\|GroupProp[pattern]` / `Value[text]` / `Coord\|Length\|GroupLength[n]` / `Id\|Lvl\|Color\|Style\|Weight\|GroupColor`; a group-source `pattern` may be several `\|`-separated alternatives; first-match wins) |
| `ARES_Text_Render` | **True** | PropertyRendering switch — the `Prop[Name]` token engine (5th OR term of `IsAnyFeatureEnabled`, so a render-only configuration still reaches `ProcessElement`) |

**Geographic reprojection output** (2026-08-27): `Coord[system,n]` / `CellCoord[pattern][system,n]` reprojects the resolved point to lat/long via `Application.CreateGCSFromKeyName(system)`, formatted `"Latitude;Longitude"`. `system` is any real Bentley GCS key name (`LL84`/`EPSG:4326` for WGS84 — the bare word `WGS84` does NOT resolve). ARES never configures a GCS itself, never calls an interactive API. Full precision when `n` omitted (unlike native `Coord[n]`'s rounded default).

**X/Y split-coordinate properties** (2026-08-26): give an ItemType exactly 2 `String` fields named `X`/`Y` (DGNLib authoring, no VBA) and a `Coord`/`CellCoord` rule targeting it writes the two axes to the two fields instead of one combined `"X;Y"` string — no grammar change, still `Prop[Name]=CellCoord[...]`. Render a single axis with `Prop[Name:X]` / `Prop[Name:Y]`. A native `Point`-typed ItemTypeProperty is NOT supported (VBA's `SetPropertyValue` doesn't document writing `Point3d`).
| `ARES_Actuate_Color` / `ARES_Actuate_Level` | False / False | PropertyActuator opt-in master switches (Color, Level). Pilot properties are fixed/reserved (`ARES_Color`/`ARES_Lvl`), attached via `PropertyTagging`'s `\|` grammar — no separate rules variable |

The full user-facing list is in the wiki: [Configuration Variables](https://github.com/Asketyll/ARES/wiki/Configuration-Variables).

## Security & licensing

None. ARES has **no licensing or copy protection** (removed) — all features run unconditionally; there is no license file, secret, or COM DLL. The `.mvba` is freely copyable. This was a deliberate decision: client-side protection in an open-source, GitHub-distributed MVBA only deterred a zero-effort copy and was not worth its complexity.

## Shared components (key APIs)

- **Geometry.bas** — pure stateless 2D: `Perp2D(A, B, Dist)` (left-hand perpendicular, zero on degenerate), `NormalizeAngle(delta, direction)` (sweep interval for `CreateArcElement2`). Shared by Zoning + RegionSplit.
- **Length.bas** — `GetLength(El, RND…)`: **Shape returns the LONGEST SIDE, not the perimeter** (for labeling). **ComplexShape returns the conduit run length** (`(Perimeter − sum of the 2 shortest sub-elements) / 2`, assuming a 2-rail + 2-cap conduit topology, with a fallback to the longest single sub-element for degenerate shapes). `GetPartialLengthInsideZones(el, zones())`: splits the element at its intersections with the zones, then classifies **each piece by its own midpoint** (`PieceInside` ray-cast) — NEVER by crossing parity, which only holds for a single convex zone and silently corrupted every multi-zone total; closed zones use the perimeter. Regression check: `CableReport.DiagZoneOverlap` grows the zone set one zone at a time - the union must never shrink, and on non-overlapping zones the sum must equal the element's own length. `RND = 255` (`ARES_RND_ERROR_VALUE`) is reserved.
- **Link.bas** — `GetLink(El, ReturnMe, FilterByTypes, MaxCount)`: elements in the same graphic group (skips `ARES_DEFAULT_GRAPHIC_GROUP_ID`).
- **StringsInEl.bas** — `GetSetTextsInEl(el, txt, Triggers, Color)`: get/set text in Text/TextNode/Cell. GET on a single `TextElement` returns a **one-element** array holding the whole string (`Split(s, "")` with a zero-length delimiter — **not** one entry per character), and on a cell returns only the LAST text-bearing sub-element — it does NOT aggregate a cell's text. Its GET semantics were frozen by Auto Lengths; that feature is gone, but the proc is still best left alone and new needs served by additions alongside it. For aggregation use `GetConcatenatedText(El, Separator)`: read-only DFS returning ALL text in an element (whole strings, text-node lines, nested cells), trimmed, empties dropped, space-joined. TextNode writes go per sub-element (the `TextLine` write property is buggy). **Targeted sub-text API (epic 15):** a single shared DFS walk assigns each text-BEARING node a **SubId** (ordinal; a TextNode counts as ONE bearer, a standalone text is SubId 0) and feeds *both* the read side — `GetConcatenatedTextExcluding(El, ExcludeIds(), nIds, Separator)`, of which `GetConcatenatedText` is now the `nIds = 0` delegator — and the write side: `EnumerateTextSubIds`, `GetTextAtSubId`, `SetTextAtSubId` (writes ONE sub-element: `IsLocked` checked on parent *and* sub, compare-before-write, TextNode line count preserved or the write refused, `ATLASCellLabelUpdate` fired only on a real change). One generator on purpose — two walks would drift the ordinal and the renderer would write into the wrong sub-text. The exclusion count is passed explicitly because VBA cannot detect an omitted `Optional` typed array. `IsNumericText` also lives here (moved from `ElementChangeHandler`); it is the **numeric gate of the D6/D7/D8 forge protection** and `PropertyRendering` is now its only caller — never copy it locally, the guarantee rests on ONE definition of numeric.
- **GetElements.bas** — `ByEE(Levels, Range, CellName, GraphicGroup, ElTypes, Colors, LineStyles, LineWeights)`: composable `ElementScanCriteria` factory; `GetLevel(name, canCreate)`; `FindNearestElement(Pt, SearchRadius, ElTypes, Levels, RequirePropertyName)`: bbox-range scan around `Pt`, nearest by bbox-centre distance, optionally only candidates carrying a non-blank value of `RequirePropertyName`; `Nothing` when none within radius.
- **CustomPropertyHandler.bas** — attaches / reads / writes ARES Item Types on elements. The definitions + value lists live in a **DGNLib** (deployed via `MS_DGNLIBLIST`), authored in the Item Types dialog — NOT created from VBA; the library is resolved with `FindForDesignFile(..., includeDgnLibs:=True)`. The managed property names are **enumerated from the DGNLib itself** — `GetCustomPropertyNames()` iterates `ItemTypeLibrary.Find("*", previous)` (the library IS the list; authoring an ItemType there is the only step; absent/empty library → `[""]`). Reads **and writes tolerate a DGNLib whose real property name differs from the ItemType name** (hand-authored libs): `GetPropertyValueFromElement` / `SetPropertyValueToElement` try the given name, then fall back to the ItemType's actual property (`ItemType.Find("*", ...)`, single-property convention); an omitted `ItemName` defaults to `PropertyName`, never "the first attached item". Reads return `Null` silently when absent; a write returns False only on a real rejection (picklist/type). `IsItemAttachedToElement(El, ItemName)` — read-only attachment check (`Items.Refresh` + `HasItems`). `RefreshItemTypes()` — refreshes MicroStation's Item Type state AND brings both libraries into the active model, on every DGN open (dialog open / UPDATEALL / SELECT ARES / SELECT ARES_SYS / SAVE / close key-in sandwich — UPDATEALL alone only refreshes what the model already knows, SELECT+SAVE is what attaches a library a DGN has never seen — then `CommandState.StartDefaultCommand`); called on DGN open, so DGNLib-deployed ItemTypes show up without restarting. `OpenCustomPropertyLibrary()` (key-in **`OpenPropertyLibrary`**) — opens the ARES DGNLib file (resolved by probing `MS_DGNLIBLIST`; the MVBA `ItemTypeLibrary` object exposes no source path) and raises the Item Types dialog on it for editing; re-opening the working file then auto-refreshes.
- **MicroStationDefinition.bas** — `StringToMsdElementType`, `IsValidElementType`, `IsRasterElement`.
- **MSGraphicalInteraction.bas** — `ZoomEl`, `HighlightEl` (transient).
- **CellRedreaw.bas** — rebuilds ATLAS leader-label cell geometry after a text edit (cells in `ARES_Cell_Is_Label_Name`).
- **FileDialogs.bas** — Save/Open dialogs by shelling PowerShell WinForms via a temp `.bat`; config import/export UI.
- **FormUXHelper.bas** — shared UX baseline for the option UserForms. `SetControlsLocked` (explicit control lock, replaces each form's copy-pasted toggle; **never disables the focused control**, so a checkbox's own `_Change` cannot eject focus); `InlineEditKey` + `NoteInlineKeyDown` + `CommitInlineEdit` + `RevertInlineEdit` (Enter commits **only if its key-down fired inside the box** — guards the reveal-button open/close flash; **Esc truly cancels** an inline edit — revert-then-commit so the live write-through sees no change); `NudgeActiveEdit` (non-blocking "finish or Esc" status cue, **no `Sleep`/`MsgBox`**); `SetTip` (localized `ControlTipText`); `PersistDefault` (restore-to-default via `.Value = .DefaultValue`, which persists — not `ResetToDefault`, which does not). The six `*_GUI_Options` forms + the length picker converge onto it instead of duplicating lock/keyboard/feedback code. Per-form baseline: a **Restore-defaults** button (`Reset_Command`), **tab order and accelerators owned by the designer** (not code), checkbox text on the checkbox `.Caption` (**Enter and Space both toggle**), and Enter/Esc return focus to the reveal button.
- **RuleGrammar.bas** — the shared rule CONDITION sub-grammar, lifted out of PropertyTagging (epic 14) so both rule families use ONE grammar: `[!]Lvl\|Cell\|Type[name\|…]`, `&` (AND), `*`/`?` wildcards (`Like`, `#`-escaped, case-insensitive), same-keyword-disjoint + Cell⇒cell-type contradiction reasoning, and the bracket-depth-aware `SplitTopLevel` / `FindTopLevelChar` / `SplitTrim` scans. Public surface: the `RuleKeyword` enum + `RuleCondition` type, `ParseCondition` (segment → condition or reason), `ConditionMatches` (condition vs element, strict negation), `ConditionToCanonical`, `ConditionsHaveContradiction(conds(), nCond, segments())`. Pure and stateless — no config, no cache, no DGN (an element only ever arrives as a matcher argument); depends on no feature module (no cross-feature coupling, no cycle). Consumed by PropertyTagging (tag rules) and PropertyCalculation (calc rules, epic 14).
- **RuleEditorUX.bas** — the reusable one-rule rule-editor UX, lifted out of `PropertyTagging_GUI_Options` (epic 14) so both options forms share the 13-3 live-hardened editor + preview without divergence. Editable-ComboBox mechanics: `SeedRulesCombo(combo, rawValue)` (`;`-split trimmed + the trailing empty "new rule" sentinel), `CaptureEditIndex(combo, curIndex)` (clean-pick / sentinel arbitration; preserves the captured index while the user types), `RebuildRules(combo, editIndex, canonical)` (replace / append / remove, sentinel excluded, `Join(";")`). Read-only coloured preview `RenderPreview(frame, sRender, bValid, redSegments(), boldKeywords())`: metachar colours (`@` pink, `&` blue, `!` orange, `*`/`?` green), keyword-bold over the passed `boldKeywords()` (bolds a bare keyword as well as `Keyword[...]`), the `MarkSegmentsRed` contradiction overlay, the runtime `MeasureCharAdvance` GDI calibration, a **fresh per-label `StdFont`** (MSForms controls share their container's Font object), explicit fixed-pitch sizing, the invalid-rule cue (ballot-X + underline), and a bounded per-Frame label lifecycle (clear-by-name-prefix — no leak). Plus `MatchComboFont`. Grammar-agnostic — **data in, no callbacks** (VBA has no method delegates): the FORM runs its grammar (validate / normalise + contradiction) and passes the render string + validity + red segments + bold list; RuleEditorUX renders runs and shows no status. Used by the Tagging + Calculation options forms.
- **FormPlacement.bas** — remembers each option form's on-screen position across sessions in the internal `ARES_Form_Layout` config var (% of the virtual desktop, one entry per form). Restored in `UserForm_Initialize` (`RestoreFormPosition`, forms are `StartUpPosition = 0 Manual`), saved in `QueryClose` (`SaveFormPosition`) + best-effort at shutdown (`OnProjectUnload` → `Command.SaveAllOpenFormPositions`). Multi-monitor via `MonitorFromRect(DEFAULTTONEAREST)`, **no hard clamp** but the caption stays grabbable, DPI read live. No stored value → centered on the primary monitor. Key-in **`ResetFormPositions`** forgets the memory and re-centers any open form live.

## Coding conventions

### Module header

Every module starts with this 4-line header (`Module:` for `.bas`, `Class Module:` for `.cls`, `UserForm:` for `.frm`):

```vba
' Module: <name>
' Description: <one line>
' License: This project is licensed under the AGPL-3.0.
' Dependencies: <comma-separated modules, or None>
```

Every module declares `Option Explicit`.

### Naming conventions

**Module/class members** — `m` + type letter (classes use `m*` too, never `p`):

| object | boolean | double | long | longlong | string | integer | byte |
|:------:|:-------:|:------:|:----:|:--------:|:------:|:-------:|:----:|
| `mo` | `mb` | `md` | `ml` | `mll` | `ms` | `mi` | `mby` |

**Locals** — `o` object · `b` boolean · `d` double · `s` string · `n` quantity/index (Long); `i`/`j`/`k` loop counters; `el`/`els` element(s). Any other `Long` takes a meaningful name (`tickNow`, `deltaMs`). **No bare `l` prefix** (avoids `1`/`I` confusion).

- Procedures: `Is…()` / `Has…()` / `Should…()` predicates; `Get…()` / `Set…()`; `Initialize…()` / `Ensure…()` / `Detect…()` / `Process…()`.
- Singleton classes use the `…Class` suffix (`ARESConfigClass`); event-handler classes have no suffix (`ElementChangeHandler`).
- `ARES_` + UPPER_SNAKE for constants and config-var handles; the config handle (`ARES_ROUNDS`) and the MS key string (`ARES_Round`) intentionally differ.

**Accepted exceptions** (do NOT "fix" these): Win32 struct fields in `ColorDialog` (`lStructSize`, `lCustData` — native API layout); a few internal members whose generic names collide as substrings with function/type names (`CellRedreaw.Delta`, `UnitTesting.TestResults`/`TestCount`/`TestElement`).

### Error handling

Standard pattern for every Public procedure:

```vba
Public Function FunctionName() As ReturnType
    On Error GoTo ErrorHandler
    ' ...
    Exit Function
ErrorHandler:
    ErrorHandler.HandleError Err.Description, Err.Number, Err.Source, "Module.FunctionName"
End Function
```

- **`HandleError(Description, Number, Source, Optional ModuleName)`** — the 4th arg is the call-site location (`"Module.Proc"`), printed as `[ModuleName]` in the log. `Number = 0` → informational formatting (no `Error N`); `Number > 0` → `Error N (Source)` + a critical MsgBox **in VBA design mode only**. There is **no severity system**.
- **Informational / non-error logs**: call `HandleError "<message>", 0, "", "Module.Proc"` (Number 0, empty Source, location in the ModuleName slot). Do NOT pass a severity word — there is no severity channel.
- **Documented exceptions** (don't "fix"): `ErrorHandlerClass` can't call itself (no logging inside it); the `UUID` module is fail-closed/silent; trivial/pure-math helpers and `Class_Terminate` use `On Error Resume Next`.

### User-facing messages vs logs

Two purposes, two channels — never conflate them:

- **Diagnostics / trapped faults** → `ErrorHandler.HandleError Desc, Number, Source, "Module.Sub"` (writes the `.log`; + a MsgBox in VBA design mode only). Log text is **English, never translated** — it must stay greppable, stable and support-readable whatever the UI language. Every `ErrorHandler:` block logs. **The log is reserved for debugging and unexpected faults**: an expected user-input refusal (e.g. a malformed rule rejected by validation, a multi-trigger config warning) is status-bar only, never logged.
- **User feedback** (command result, validation abort, actionable progress, interactive-tool guidance) → the MicroStation status bar, **always translated**:
  - parameter-less status → `LangManager.ShowStatusT "Key"` (self-initialises the translation system, no English fallback needed);
  - status carrying an identifier/count → `ShowStatus GetTranslation("Key", arg0, …)`;
  - interactive tool prompts → `ShowCommand` / `ShowPrompt GetTranslation(...)`.

Rules:
- **Raw `Err.Description` never reaches the status bar** — the detail goes to the `.log`; the user sees a translated line.
- **Key-in faults**: `Command.bas` traps every fault with `ReportFailure "SubName", Err.Description, Err.Number, Err.Source` — one private helper that logs the detail *and* shows the generic translated `CommandFailed` (`"{0} failed"`). A key-in living in another module does the same two steps inline.
- **Silently-swallowed faults**: most `ErrorHandler:` blocks log then *swallow* (no re-raise), so a fault caught in a called module never reaches the command's handler and would leave the user with a silent no-op. `ErrorHandlerClass` therefore carries a `HadError` flag (set on any `Number > 0` log); each **synchronous** key-in calls `ErrorHandler.ClearErrorFlag` on entry and `ReportIfLogged "SubName"` before returning, surfacing `CommandFailed` **once** if anything faulted downstream. The flag keys on `Number > 0` only, so expected/validation logs (`Number 0`, already self-reported) don't trip it. **Interactive** key-ins (`SplitRegion`) are excluded — their work is deferred to a self-reporting locate tool, so a start/end check wouldn't see it.
- **Identifiers stay literal**: config-var / key-in / level / type names go through `{0}` params, never inside translated prose.
- **No `MsgBox` for normal feedback** — use the status bar. `MsgBox` is reserved for: the design-mode `HandleError` popup, interactive confirmations (yes/no), the language-selection prompt, in-modal-form validation, a summary needing acknowledgment (e.g. `ShowARESConfigSummary`), and bootstrap-failure messages that predate translations.
- **Verbose intermediate progress** is a diagnostic, not user feedback → log it (`HandleError "<step>", 0, "", "Module.Sub"`), don't put it on the status bar (see `ExportLengthInRegion`).
- Every message is a paired `EN_`/`FR_` key in `LangManager`; add both. Switching language (`English`/`Français`) reloads translations so the confirmation shows in the resolved language.

### Recurring patterns

1. **Guard / early-exit**: `If oElement Is Nothing Then Exit Sub` / `If Not ARESConfig.IsInitialized Then Exit Sub` / feature-flag checks first.
2. **Find-or-create**: `FindByName` → `If Nothing Then CreateNew`.
3. **Idempotent idle-handler registration**: single persistent instance, add/remove from the idle list only. Anti-GC: hold one-shot handlers (e.g. `moReRegHandler`) as Private members, not `Dim` locals.
4. **Near-origin precision workaround** (Zoning + RegionSplit + RegionMerge): region boolean ops (`GetRegionUnion` / `GetRegionDifference`) misbehave at large coordinates — translate operands by `-Range.High`, operate, translate results back.
5. **Config write-through**: assigning `ARES_MS_VAR_Class.Value` persists to MicroStation; `Config.RemoveValue` is a soft delete (sets `""`).
6. **Add-before-symbology**: a new element's Level/symbology can only be set once it is a model member — `AddElement` first, then set Level/Color/Style/Weight, then `Rewrite`.

## Code review — mandatory blockers

A review MUST flag these as **BLOCKER** (not nit):

- Module without `Option Explicit`.
- `Public` Function/Sub without `On Error GoTo ErrorHandler` + the standard `HandleError` (unless a documented exception above).
- Any MVBA type/object/method/property used without verifying its signature in the [MVBA docs](https://github.com/Asketyll/mvba-docs-in-md-for-ai) (the specific page, not just the index).
- `Element.ID` (DLong) used without DLong helpers; an element modified without `.Rewrite`.
- A new geometry feature that deletes/overwrites before both replacement elements are validated and added (anti-destructive invariant).
- Any direct **USER-property value write** inside `PropertyRendering` (a `SetPropertyValueToElement` that does not name `ARES_NAME_LIBRARY_SYS`), or an attach/detach that bypasses the `PropertyTagging` wrappers — the same doctrine blocker `PropertyCalculation` already carries for attaches. Each engine writes exactly one thing: Tagging the attachment, Calculation the value, Actuator the graphic attribute (Color/Level), Rendering the text.

## MVBA documentation & pitfalls

- **API reference**: a Markdown mirror of the MVBA object model is published at
  https://github.com/Asketyll/mvba-docs-in-md-for-ai (categories `01-types-enums/` … `06-examples/`). In `01-types-enums/`, each type's page lists in its **Remarks** the methods usable with that type — start there, then open the specific method page. Verify any type/object/method/property against it before use.
- **High-frequency pitfalls**:
  - `Element.ID` is a **DLong** — use the DLong helpers, never treat it as a plain Long.
  - An element edited in place is not persisted until `.Rewrite`.
  - `GetSetTextsInEl` GET on a single `TextElement` returns a **per-character** array.
  - Region boolean ops are unstable far from the origin (see the near-origin workaround).
  - Win32 handles must be `LongPtr` under VBA7.
